\section{Evaluation}
\label{sec:experiments}

We separate \emph{mechanism feasibility} from final task quality. RQ1 keeps the first completed Stage-A checkpoint (\textbf{StageA-v0}) because its failure is diagnostic: several CID interaction heads are learned, but the original runtime cannot reach them reliably. RQ2 and later experiments instead use a model retrained from the same base after correcting the identified train--runtime inconsistencies. Full hyperparameters, data composition, checkpoint identity, and raw traces appear in \cref{app:reproducibility} and the public artifact.\footnote{\url{https://huggingface.co/fwerkor/CID-RQ1-StageA-v0}}

\subsection{Research Questions}

\paragraph{RQ1: Is the CID interaction mechanism learnable?}
Measure information-need, source, argument, binding, observation, and projection behavior in StageA-v0, separating learned heads from runtime materialization.

\paragraph{RQ2: Does a consistent train--runtime contract yield reliable end-to-end CID?}
Retrain from the base model after the RQ1 fixes, then measure tool recall, observation coverage, convergence, and final answer quality without diagnostic intervention.

\paragraph{RQ3: Can persistent bindings hide external latency?}
Vary source latency at fixed logical model compute and compare end-to-end latency at matched answer quality.

\paragraph{RQ4: Does repeated perception improve assimilation?}
Compare one-time injection, cached re-projection, fixed polling, and need-conditioned refresh on static and dynamic sources.

\paragraph{RQ5: Is the Typed Cognitive Tensor necessary?}
Compare natural-language thought, untyped latent state, and the proposed \tct on accuracy, binding stability, grounding, revision locality, and inspectability.

\paragraph{RQ6: Is diffusion essential?}
Compare CID with an asynchronous autoregressive model using matched sources, data, and approximate compute; gains must come from revisability, not asynchronous I/O alone.

\subsection{RQ1: StageA-v0 Mechanism Study}
\label{sec:rq1}

\paragraph{Protocol.}
StageA-v0 freezes the iLLaDA-8B backbone and trains 453.8M CID-specific parameters. We use 32 deterministic Natural Questions examples from the pinned official \texttt{nq\_open} \emph{validation} parquet; CID training uses only the upstream NQ-Open train split. Each probe requires one \texttt{knowledge\_search} observation. Evaluation uses four denoising updates per runtime step and a 16-step cap. The original runtime has a 128-slot TCT and allocation threshold 0.8. A diagnostic materializer then changes no weights: if no allocation crosses the threshold, it selects one bootstrap candidate and subsequently the highest-need eligible empty slot. We test this fallback at both the original 128-slot geometry and the typical eight-slot NQ training geometry.

\paragraph{Results.}
Teacher-forced diagnosis shows a sharp separation. Across 219 positive allocation targets, mean allocation probability is 0.110 and 0/219 reaches the runtime threshold of 0.8. In contrast, 165 positive information-need decisions average 0.741; source selection is correct in 165/165 cases; required-argument presence averages 0.99994; and argument-grounding cosine similarity averages 0.817. This explains the end-to-end contrast in \cref{tab:rq1-mechanism}: changing only allocation selection at 128 slots recovers the complete need$\rightarrow$binding$\rightarrow$tool$\rightarrow$observation$\rightarrow$projection path on 29/32 cases, and matching the common eight-slot training geometry raises this to 30/32. Allocation semantics are therefore the dominant blocker, while geometry is a smaller additional mismatch.

\paragraph{Failure analysis.}
RQ1 exposed three contract defects:
\begin{enumerate}[leftmargin=*,nosep]
  \item teacher schedules randomize physical TCT slots, while StageA-v0 applies exact per-slot BCE to the random slot, making the physical label unidentifiable from semantics;
  \item common NQ training tensors use eight thought positions while the default runtime presents 128, shifting prompt/display logical positions by roughly 120 positions;
  \item training allows intermediate display targets to change token length, whereas runtime \texttt{DisplayCanvas} length is fixed.
\end{enumerate}
The display head is also undertrained: even with the correct percept teacher-forced, exact final-display recovery is only 1--4/32 across tested diffusion times. A strict ten-case compositional holdout obtains 6/10 exact, so StageA-v0 is not a dead checkpoint, but it is not an end-to-end QA result. We therefore answer RQ1 narrowly and positively---the interaction chain is learnable---while retaining the systems failure as a negative finding.

\subsection{RQ2 Boundary: Corrected Retraining}
\label{sec:rq2}

RQ2 starts from the base model again, not StageA-v0. The corrected contract removes arbitrary physical-slot identity from allocation, makes logical positions independent of unused TCT capacity, and represents display as a fixed physical budget with explicit realized-length/termination semantics. Stage A is retrained first; only then is the backbone unfrozen for Stage B. Final RQ2 hyperparameters are frozen from checkpoint metadata before RQ2--RQ6 results are accepted, so pre-fix Stage-B smoke runs are not counted as experiments.

The complete RQ3--RQ6 task families, baselines, metrics, timing definitions, and ablations are specified in \cref{app:reproducibility}. CID is falsified if corrected retraining still yields unreliable bindings, post-arrival revision destroys more correct state than it repairs, waiting-time computation is mostly discarded, or a matched asynchronous AR baseline reaches the same quality and latency with lower complexity. RQ1 already demonstrates that a semantically arbitrary physical-slot objective can block an otherwise useful interaction policy.
