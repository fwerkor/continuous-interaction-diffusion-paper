\begin{abstract}
Large language models increasingly rely on external tools to access up-to-date information, perform computation, and interact with the outside world. For autoregressive models, tool use naturally fits the generation process: the model emits a tool call, waits for the result, and then continues generating. Diffusion language models (dLLMs), however, reason by repeatedly refining many parts of their output in parallel, making this stop-and-resume interaction pattern unnecessarily restrictive. It can force tool decisions before the model's reasoning has stabilized, delay useful observations until a discrete call finishes, and introduce redundant refinement and tool execution, ultimately hurting both task accuracy and inference efficiency.

We introduce \emph{Continuous Interaction Diffusion} (CID), a diffusion-native model--runtime architecture that integrates tool interaction into the iterative denoising process. CID separates system state into three coupled channels: an externally controlled, model-read-only fact channel; a thought channel represented by a \emph{Typed Cognitive Tensor}; and a display channel that converges to the user-visible response. Information needs emerge as typed latent states in the thought channel, and a model-side intent adapter maps them to registered external sources. The runtime turns persistent information needs into \emph{perceptual bindings}, launches reads asynchronously while model denoising continues, and projects returned results into the evolving thought state. Static results can be re-projected from cache without repeated external execution, while changing sources can be refreshed or streamed through the same binding. These mechanisms allow useful external information to influence reasoning earlier, overlap tool latency with model computation, and let new evidence revise already formed cognition and display state within the same diffusion trajectory. We formalize the channel semantics, Typed Cognitive Tensor, binding lifecycle, asynchronous runtime, and training objectives, and provide a falsifiable evaluation protocol focused on task quality and end-to-end efficiency. This first paper focuses on read-only tools and defines the architecture without making empirical performance claims.
\end{abstract}
